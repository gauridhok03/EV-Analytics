# EV Charging Station Utilization and Reliability Analytics Platform

> **All data is SIMULATED.** Stations are fictional ("VoltHub ..."); sessions, outages and tariffs are generated by
> `services/data_generator.py`. Nothing here is real operations data.

Streamlit + PostgreSQL + Pandas/NumPy + Plotly + SQLAlchemy. Free and open source.

## 1. Install
```bash
python -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## 2. Configure PostgreSQL
1. Install PostgreSQL 14+ from https://www.postgresql.org/download/ (remember the `postgres` user's password).
2. Create the databases (psql, pgAdmin, or `createdb`):
   ```sql
   CREATE DATABASE ev_analytics;
   CREATE DATABASE ev_analytics_test;   -- optional; used only by the tests, whose tables get DROPPED
   ```
3. Copy `.env.example` to `.env` and set your password / host / port:
   ```
   DATABASE_URL=postgresql+psycopg2://postgres:YOUR_PASSWORD@localhost:5432/ev_analytics
   ```

## 3. Create the tables and load the simulated data
```bash
python database.py --check              # connection test
python database.py --reset              # drop + create tables + load the CSVs in data/
python database.py --generate --reset   # optional: regenerate fresh simulated CSVs first
```
(You can also just start the app: if the database is empty it offers a button that does the same thing.)

## 4. Run
```bash
streamlit run app.py
```
In VS Code: open the folder, select the `.venv` interpreter, then run the command above in the integrated terminal.

## 6. Definitions (also shown in the app)
* **Reporting period**: start date 00:00 to the end of the end date (naive local time, no timezone conversion).
* **Utilization %** = occupied time / available time x 100. Available = period - downtime. Occupied = *union* of session intervals
  (overlaps counted once) minus time the charger was down. Station utilization is time-weighted across its chargers.
* **Downtime** = union of outage intervals (overlapping outages merged); ongoing outages run to the end of the period.
* **Availability %** = (period - downtime) / period. Station availability = 1 - charger downtime / (chargers x period).
* **MTTR** = downtime / outages. **MTBF** = uptime / outages (undefined when there are no outages).
* **Analytics eligibility**: valid sessions, plus sessions whose *only* issue is an overlap (switchable). Sessions with any other error
  are excluded until corrected. Nothing is ever deleted automatically.
* **Validation rules**: missing start, missing end, end not after start, duplicate session ID, negative energy, invalid timestamp
  (unparseable text, before year 2000, more than 1 day in the future), session longer than 24 h, overlap on the same charger.

## 7. Database
`sql/schema.sql`: `tariffs`, `stations`, `chargers`, `charging_sessions`, `energy_records`, `outage_events`.
Sessions and outages reference `(charger_id, station_id)` through a composite foreign key, so a session always belongs to a charger
and that charger to its station. `session_id` is intentionally not unique (duplicates must be storable to be reported); `start_ts`/`end_ts`
are nullable and unparseable input is kept in `start_raw`/`end_raw`. Foreign keys use `ON DELETE RESTRICT`; the app removes a station's
children explicitly in one transaction after confirmation.

## 9. Known limitations
* Developed and tested on Linux with PostgreSQL 16, Python 3.12, Streamlit 1.67, pandas 3.0. Not run on Windows/macOS.
* The visual design could not be inspected in a real browser during development; pages are verified to render without errors,
  but spacing/colours should be checked by eye. Streamlit's native widget theme switch is best-effort; charts and cards always follow the toggle.
* The station map loads OpenStreetMap tiles in the browser, so it needs internet access.
* Timestamps are naive local time. Sessions longer than 24 h cannot be saved through the forms (change `MAX_SESSION_HOURS` in `config.py`).
* Authentication/roles are out of scope.
